The first asset release (assets-1) proved swaps and token payouts on Chipnet and Paytaca phone signing. The revised anchor (assets-2) binds owner cancellation to a new active round and applies the review period to owner-sponsored payouts. The BCH lifecycle records are in v2-live.md.

Application

Published app: https://astrorehan.github.io/pusaka-bch/ (mainnet) and https://astrorehan.github.io/pusaka-bch/chipnet/ (Chipnet). Example plans: /wallet/demo on either.

The desktop sidebar folds into a rail. Phones use a drawer. Wallet, inheritance, activity, setup and swap are separate routes. Transaction dialogs show recipients, fees, protected change and returned authorization funds before signing.

app/src/lib/protocol/ contains the browser-safe codecs, artifacts and builders. The contract runner re-exports the same module. No filesystem loaders, test keys, mnemonics or chain runners enter the client bundle. npm run check:artifacts compares all six bundled artifacts with compiler output.

The app discovers live plan/inbox/token UTXOs and uses confirmed-anchor chain age for review readiness. It checks for stale plan state before signing. Wallet rejection, quote expiry and ambiguous broadcast failure are explicit outcomes. Local activity records say Accepted, not confirmed. Explorer links let users inspect confirmations; importing a plan does not pretend to import its history.

Onboarding keeps an ordinary owner coin of at least 600 sats, separate from the 1,000-sat plan identity. A separately reviewed preparation transaction can gather ordinary HD wallet coins into the first receive address. Each owner action still requires normal wallet approval. A plan link or JSON restores public state without holding a spending key. Saved browser data is a convenience, not the sole backup.

/plan and /legacy/new retain the v1 code path. New setup at /new and /wallet/new creates the asset-enabled revision. Existing contracts do not upgrade.

Asset revision

The first asset release retained version: pusaka-v2 and added protocolRevision: assets-1. Missing revision selects the original v2 artifact. Unknown revisions fail closed. The new PusakaAssetPlan retains the prior state machine and adds:

  • assetAction(maximumDebit): owner co-signature, bounded approved BCH debit, identity preservation, deadline renewal, round advancement and review cancellation.
  • assetDistribution(): a public co-spend of a PAID_OUT plan that preserves its complete state and BCH. It lets the token covenant authenticate the current policy.

PusakaTokenVault binds the immutable plan identity and locking script. An owner token send co-spends the plan, renewing activity. Public token payout requires a completed BCH claim and the current policy preimage. Old policy links cannot redirect a payout. Token carriers and payout fees come from the submitter's ordinary BCH, while the plan and receipt BCH remain preserved.

Fungible amounts use integer floor shares. All indivisible rounding units go to the final configured heir. A tiny receipt may give zero token units to earlier heirs; their carrier outputs remain plain BCH. No token units are burned or left as an unclaimable remainder. NFTs and arbitrary DeFi positions are outside this flow.

Supported swap

The supported pair is BCH / PSK on Chipnet, using a real Cauldron V0 pool. PSK is a test fungible token with no monetary value. Mainnet trading stays unavailable until a real pair and phone signing have been qualified.

The adapter uses @cashlab/cauldron to derive the actual pool script and unlocker. It verifies that the configured pool address matches that script, reconstructs the pool at its input index, applies the pool's 0.3% liquidity fee and checks a positive minimum return. Quotes expire after 60 seconds. A conflicting pool spend invalidates the whole transaction. The owner's signature commits to exact outputs.

One atomic swap spends protected BCH, renews activity, returns the ordinary auth coin, recreates the pool and pays fungible proceeds directly to the token vault. There is no intermediate unprotected owner token output or separate allocation. The UI supports BCH-to-token purchase for this pair, not arbitrary pairs or sales. Protocol reference: https://docs.riftenlabs.com/cauldron/swap/

Automated qualification

  • Compiler: all 12 contract files compile without errors.
  • SolidHat contract tests: 61/61 pass (npm test in contract/) under the BCH 2026 VM and a strict BIP68 verifier. The v2, metadata, review and asset suites cover actual pool script execution, early payout rejection, recipient hijack, policy changes, 10 heirs, tiny indivisible amounts, partial token sends, protected token change, expired quotes and theft; the rest cover v1 and stages 1 and 2.
  • Review anchor regressions cover owner-sponsored payout before and after maturity, all owner actions that cancel a review, and invalid cancellation successors. Earlier plan links still reconstruct their own addresses.
  • Wallet and transaction regressions: 11/11 pass in the same suite. They cover small-plan funding, sponsored collection, token-only exit, recovery after a lost creation or edit response, and spent inputs after signing.
  • WizardConnect actual JSON transport: 3/3 pass, including tampered-output rejection.
  • Browser tests: 6/6 pass (npm run test:ui in app/). They exercise setup validation, the desktop, tablet and phone layouts, a live public Chipnet plan without signing, recoverable errors, wallet pairing and the landing page.
  • Normal, mainnet and hosted-path production builds pass TypeScript and Vite.

These are selected applicable tests, not a claim that every historical scratch test in this repository passes. Mainnet builds compiling does not prove mainnet execution. A phone-sized browser viewport does not prove Paytaca mobile signing.

Mainnet v2

The lifecycle ran on mainnet with the same builders as the app. The network accepted creation, collection, owner spending, contact approvals, owner cancellation and the payout from a mature claim. The revised anchor also passed a mainnet check where the owner signed and sponsored an early payout and the network refused it. The wallet-free demo opens a ready assets-2 example from a pool of four, with six earlier plans as fallbacks. Mainnet transaction record
